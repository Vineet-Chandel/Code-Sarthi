## ❯ The Problem

Developers juggle **10+ disconnected tools** across their career journey:

```
Resume Builders   ATS Checkers   LinkedIn   GitHub   Discord   Slack
      Zoom             Trello        Notion      Interview Platforms ...
```

Every tool speaks a different language, holds a different slice of the same career, and demands a separate login. The result is scattered workflows, duplicated effort, inconsistent resumes, and hours lost to context-switching instead of actual growth.

**CodeSarthi eliminates the fragmentation** — one profile, one AI layer, every workflow a developer's career actually needs.

---

## ❯ What is CodeSarthi?

CodeSarthi is an **AI-powered career acceleration and developer collaboration ecosystem** — a unified platform where developers can:

- ✦ Build AI-optimized resumes tailored to specific job descriptions
- ✦ Get real-time AI coaching through mock interviews
- ✦ Collaborate with teams through integrated messaging and voice/video
- ✦ Track projects with an AI project manager
- ✦ Grow their career with **Shastra AI** — a persistent, intelligent career companion

> **Vision:** *Empowering every developer with AI to build, collaborate, and grow their career — without switching platforms.*

## ❯ Platform Architecture

CodeSarthi is built as a layered system — each layer independently scalable, cleanly separated, and designed to feel like enterprise-grade software.

```
┌──────────────────────────────────────────────────────────────────────┐
│                              CLIENT LAYER                             │
│           React 19 · Vite 7 · Tailwind CSS · Redux Toolkit            │
└───────────────────────────────┬─────────────────────────────────────┘
                                 │  REST + WebSocket
┌───────────────────────────────▼─────────────────────────────────────┐
│                             BACKEND LAYER                             │
│              Node.js 18+ · Express 5 · JWT Auth · Middleware          │
└───────────────────────────────┬─────────────────────────────────────┘
                                 │
┌───────────────────────────────▼─────────────────────────────────────┐
│                               AI LAYER                                 │
│         Groq SDK · LLaMA 3.3 70B · 9-Stage Resume Pipeline            │
└───────────────────────────────┬─────────────────────────────────────┘
                                 │
┌───────────────────────────────▼─────────────────────────────────────┐
│                             DATABASE LAYER                             │
│                    MongoDB · Mongoose ODM · Redis Cache               │
└───────────────────────────────┬─────────────────────────────────────┘
                                 │
┌───────────────────────────────▼─────────────────────────────────────┐
│                            REALTIME LAYER                              │
│              Socket.IO · WebRTC · Presence · Live Sync                │
└───────────────────────────────┬─────────────────────────────────────┘
                                 │
┌───────────────────────────────▼─────────────────────────────────────┐
│                          EXTERNAL SERVICES                             │
│        Cloudinary (Media) · Resend / Nodemailer (Email) · Groq API    │
└──────────────────────────────────────────────────────────────────────┘
```

Every request flows top-down through a predictable, testable path — client → API → AI reasoning → persistence → real-time propagation — keeping the system observable and easy to extend.

### 📄 Resume Intelligence Engine — 9-Stage AI Pipeline

The flagship feature. Not just a resume builder — a full intelligence pipeline that analyzes, rewrites, and optimizes resumes the way a senior technical recruiter would.

```
┌─────────────┐    ┌─────────────────┐    ┌─────────────────────────────┐
│   Stage 1   │    │     Stage 2     │    │         Stages 3–6          │
│             │    │                 │    │           (Parallel)         │
│   Profile   │───▶│    Targeting    │───▶│  Summary  │  Experience      │
│    Audit    │    │     Strategy    │    │  Rewrite  │  Rewrite         │
│             │    │                 │    │  Projects │  Skills Optim.   │
└─────────────┘    └─────────────────┘    └─────────────────────────────┘
       │                    │                            │
       ▼                    ▼                            ▼
  Health Score        JD Blueprint                Recruiter-Ready
  Strengths            Keyword Map                 Section Content
  Weaknesses           Positioning

┌─────────────┐    ┌─────────────────┐    ┌─────────────────────────────┐
│   Stage 7   │    │     Stage 8     │    │           Stage 9           │
│             │    │                 │    │                              │
│   Resume    │───▶│  ATS Analysis   │───▶│   Skill Gap Analysis        │
│  Assembly   │    │                 │    │     + Learning Roadmap      │
└─────────────┘    └─────────────────┘    └─────────────────────────────┘
                     ATS Score               Coverage %
                     Format Score             Missing Tech
                     Readability               Certifications
```

**Stage 1 — Profile Audit**
Evaluates ATS readiness, formatting, keyword density, and action-verb quality — producing a health score with prioritized improvements.

**Stage 2 — Targeting Strategy**
Reads the job description and produces a positioning blueprint: recruiter narrative, must-use keywords, tone instructions, and words to avoid.

**Stages 3–6 — Parallel Rewrite** *(executed concurrently via `Promise.all`)*
Rewrites Summary, Experience bullets, Projects, and Skills against the Stage 2 blueprint.

<details>
<summary><b>Example transformation</b></summary>

```diff
- Worked on React project.
+ Developed scalable React applications serving 5,000+ users,
+ improving rendering performance by 42%.
```

</details>

**Stage 7 — Assembly**
Merges every optimized section into a unified, coherent resume.

**Stage 8 — ATS Analysis**
Returns a comprehensive score across keyword coverage, formatting, and recruiter-friendliness.

**Stage 9 — Skill Gap Analysis**
Compares candidate skills against job requirements and produces a prioritized learning roadmap with certification recommendations.

> All nine stages are orchestrated server-side, with a pure-JS assembly route and structured `_tailoringMeta` returned for full transparency into every AI decision.

## ❯ Quick Start

### Frontend

```bash
# Clone the frontend
git clone https://github.com/codesarthi/codesarthi-front.git
cd codesarthi-front

# Install dependencies
npm install

# Start dev server
npm run dev

# Build for production
npm run build

# Preview production build
npm run preview
```

### Backend

```bash
# Clone the backend
git clone https://github.com/Vineet-Chandel/codesarthi-backend.git
cd codesarthi-backend
npm install

# Configure environment
cp .env.example .env
# Fill in: MONGO_URI, JWT_SECRET, GROQ_API_KEY, CLOUDINARY_*, REDIS_URL, RESEND_API_KEY

npm run dev    # development (nodemon)
npm start      # production
```

5. **Commit** with clear, descriptive messages
6. **Push** to your fork and open a **Pull Request** against `main`

Please open an issue first for significant changes, so the direction can be discussed before implementation work begins.

---

## ❯ Development Workflow

```
main            → production-ready, always deployable
  └── develop   → integration branch for upcoming release
        └── feature/*   → individual features
        └── fix/*        → bug fixes
        └── chore/*       → tooling, config, docs
```

- Branch from `develop`, not `main`
- Keep pull requests focused and reasonably small
- Rebase before opening a PR to keep history clean
- Squash-merge feature branches once approved

## ❯ Code Standards

| Area | Standard |
|---|---|
| Formatting | Prettier + ESLint, run before every commit |
| Naming | `camelCase` for variables/functions, `PascalCase` for components |
| Components | Self-contained, single-responsibility, colocated styles |
| Pull Requests | Clear title, linked issue, concise description of changes |
| Testing | New logic should include reasonable test coverage where applicable |
| Documentation | Update relevant docs/comments alongside any behavioral change |
